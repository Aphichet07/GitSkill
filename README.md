# GitSkill
GitSkill คือแพลตฟอร์มสำหรับวิเคราะห์และประเมินทักษะการเขียนโปรแกรมจาก GitHub Repository โดยผู้ใช้งานสามารถเลือก Repository หลายๆ ตัวมารวมกลุ่มกันเป็น Portfolio จากนั้นระบบจะทำหน้าที่เสมือน Senior Software Engineer เข้ามาสแกนและรีวิวซอร์สโค้ดทั้งหมดแบบเจาะลึก

เป้าหมายของโปรเจคนี้คือการให้คะแนนทักษะนักพัฒนาแบบรอบด้าน (เต็ม 100 คะแนน) พร้อมระบบตัดเกรดตั้งแต่ S ถึง F โดยประเมินจากเกณฑ์ 8 มิติหลัก ได้แก่:

* Documentation: การเขียน README และ License

* Architecture: การจัดโครงสร้างโปรเจคและจัดการ Dependencies

* Test & CI/CD: การเขียนระบบทดสอบและระบบอัตโนมัติ

* Clean Code: ความเป็นระเบียบและความซ้ำซ้อนของโค้ด

* Code Efficiency: ประสิทธิภาพในการทำงานของโค้ด (เช่น การหลีกเลี่ยงลูปซ้อนลูป)

* Security: ความปลอดภัยและการป้องกันข้อมูลสำคัญหลุด

* Developer Habits: นิสัยการเขียนโค้ด เช่น การเขียนคอมเมนต์ และการลบโค้ดขยะ

* Language Mastery: ความเชี่ยวชาญในการเขียนโค้ดตามมาตรฐานของภาษานั้นๆ

# Tech Stack
ระบบนี้ใช้สถาปัตยกรรมแบบแยกส่วน (Frontend และ Backend) และเลือกใช้ฐานข้อมูล 2 รูปแบบเพื่อความเหมาะสมของข้อมูล:

### Frontend:
* Next.js
* Tailwind CSS
* shadcn/ui
* Axios

### Backend:
* Node.js & Express.js
* TypeScript
* AI Integration

### Database:
* PostgreSQL + Prisma
* MongoDB

# โครงสร้างโปรเจค

``` bash
GitSkill/
|
|-- client/                 # ส่วนหน้าบ้าน 
|   |-- app/                # โฟลเดอร์หลักสำหรับจัดการ Routing ของหน้าเว็บทั้งหมด
|   |   |-- dashboard/      # หน้ากระดานควบคุมสำหรับผู้ใช้งานที่เข้าสู่ระบบแล้ว
|   |   |-- home/           # หน้าแรกของเว็บไซต์ (Landing Page)
|   |   |-- test/           # หน้าสำหรับการทดสอบระบบ
|   |   |-- layout.tsx      # โครงสร้าง Layout หลักที่ใช้ร่วมกันทุกหน้า
|   |   |-- page.tsx        # จุดเริ่มต้นของหน้าเว็บ
|   |   |-- globals.css     # ไฟล์จัดการสไตล์ CSS หลักของโปรเจค
|   |
|   |-- asset/              # โฟลเดอร์สำหรับเก็บไฟล์ทรัพยากรต่างๆ เช่น รูปภาพ
|   |-- component/          # โฟลเดอร์เก็บ UI Component ย่อยที่พัฒนาขึ้นมาเอง
|   |   |-- modals/         # โฟลเดอร์สำหรับเก็บหน้าต่าง Pop-up (เช่น หน้าแสดงผลคะแนน)
|   |   |-- ui/             # โฟลเดอร์ย่อยสำหรับ UI พื้นฐาน
|   |
|   |-- components/         # โฟลเดอร์สำหรับเก็บ Component จากไลบรารีภายนอก (เช่น shadcn/ui)
|   |-- lib/                # โฟลเดอร์สำหรับเก็บฟังก์ชันช่วยเหลือ (Utility) และการตั้งค่าไลบรารี
|   |-- public/             # โฟลเดอร์เก็บไฟล์ที่ต้องการให้เข้าถึงได้แบบสาธารณะ
|   |-- next.config.ts      # ไฟล์ตั้งค่าการทำงานของ Next.js
|   |-- package.json        # ไฟล์จัดการ Dependencies ของฝั่ง Frontend
|
|-- server/                 # ส่วนหลังบ้าน 
|   |-- controllers/        # ตัวควบคุม Logic การรับคำขอ (Request) และส่งผลลัพธ์ (Response) กลับไปยังหน้าเว็บ
|   |-- generated/          # โฟลเดอร์เก็บไฟล์ที่ระบบสร้างขึ้นอัตโนมัติ 
|   |-- lib/                # ไฟล์ตั้งค่าและฟังก์ชันส่วนกลาง เช่น การเชื่อมต่อฐานข้อมูล MongoDB และ PostgreSQL
|   |-- middleware/         # ฟังก์ชันคั่นกลางสำหรับตรวจสอบข้อมูลก่อนเข้าถึง API เช่น การยืนยันตัวตน (Authentication)
|   |-- models/             # โครงสร้างฐานข้อมูล (Schema) สำหรับฝั่ง MongoDB (ใช้ Mongoose)
|   |-- prisma/             # โฟลเดอร์เก็บไฟล์ Schema และข้อมูลการ Migration สำหรับฝั่ง PostgreSQL
|   |-- routes/             # ส่วนกำหนดเส้นทาง (Endpoint) ของ API ทั้งหมดในระบบ
|   |-- services/           # ส่วนประมวลผล Business Logic เช่น การทำงานของ AI และการคำนวณคะแนน
|   |-- types/              # ไฟล์กำหนดชนิดข้อมูล (Type Definitions) เพื่อควบคุมความถูกต้องของ TypeScript
|   |-- .env                # ไฟล์เก็บตัวแปรสภาพแวดล้อม เช่น รหัสผ่านฐานข้อมูล หรือ API Key (ไม่นำขึ้น Git)
|   |-- package.json        # ไฟล์จัดการรายการไลบรารีและคำสั่งสคริปต์ของฝั่ง Backend
|   |-- prisma.config.ts    # ไฟล์การตั้งค่าเพิ่มเติมสำหรับ Prisma ORM
|   |-- server.ts           # ไฟล์หลัก (Entry Point) สำหรับเริ่มต้นเปิดการทำงานของเซิร์ฟเวอร์
|   |-- tsconfig.json       # ไฟล์ตั้งค่าการทำงานและกฎเกณฑ์ต่างๆ ของ TypeScript
|
|-- package.json            # ไฟล์จัดการ Dependencies ของโปรเจค
|-- README.md               # ไฟล์อธิบายรายละเอียดโปรเจค
```
